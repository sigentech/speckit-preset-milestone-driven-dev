## 目的

移植自 grill-me / grilling 技能：当用户想深挖一个想法、压力测试一个方案、或把脑子里模糊的决定逼问清楚时，对用户进行一场"毫不留情的访谈"。不替用户做决定，只把每一个隐含假设逼到明面上。

**流程定位**：旁路技能，可在流程**任何环节**调用（里程碑规划前、Demo 迭代中、spec/plan 撰写中、分析消除时、发布回顾时均可）；不改变主线状态，只把共识结论沉淀到当前环节的正式产物。

## 用户输入

~~~text
$ARGUMENTS
~~~

用户给出的待深挖主题（一个计划、一个决策、一个想法）；缺省时先判定当前环节（见下表），就当前环节最悬而未决的事项开问。

## 核心方法：设计树与逐轮前沿

把主题映射为一棵**设计树**：每个决策都分叉出挂在它之下的子决策。

按**轮次**推进。**前沿**（frontier）= 所有前置条件已尘埃落定的决策，即现在就能问、而不必猜用户尚未给出的答案的问题。一轮之内问完整个前沿：给每个问题编号，并附上你的推荐答案。然后停下来等用户回答，再进入下一轮。

一轮的格式如下：

~~~
❓ **Q1** - **<问题标题>**：<问题正文，可含多个段落、多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
~~~

措辞上让"是/同意"即等于接受你的推荐答案。

用户的每轮回答都会重塑设计树：已敲定的决策把前沿向外推，解锁依赖它们的下游问题。每轮结束重新计算前沿，再发起下一轮。一个问题的答案若依赖本轮另一个仍开放的问题，它属于**更靠后的轮次**，不属于本轮。

**查事实是你的工作，永远不是用户的。** 前沿问题需要环境事实（文件系统、代码、工具输出等）时，自己去查（宿主支持子代理时派子代理去查）；绝不向用户索要你自己能查到的东西。不要因此阻塞：进行中的探查是一项未决前置，只有它下游的问题等待结果，前沿的其余问题照问。**决策才是用户的**：逐条摆给用户，等回答。

**结束条件**：前沿清空——设计树的每个分支都已走到，没有任何被默默假设掉的东西。在用户确认"已达成共识"之前，不得据此动手实施。

## 结论沉淀：落点必须与调用时所在环节吻合

达成共识后，把敲定的结论写入**当前环节对应的正式产物**，不另起游离文件。

**项目前期（尚无正式产物可承接时）统一落"探索登记处"**：宪法/PRD/里程碑规划尚未完成的阶段，结论写入 `docs/explore/YYYY-MM-DD-<主题>-grill.md`（从 `explore-note-template` 生成，用 `specify preset resolve explore-note-template` 定位），frontmatter 置 `status: pending-absorb`。该目录是下游命令的**自动吸收源**：`speckit.prd`、`speckit.milestones init` 执行时会扫描其中待吸收文件作为愿景素材，吸收后回写状态——无需用户手工搬运。

| 调用时环节（证据） | 结论落点 |
| --- | --- |
| 无 `.specify/memory/constitution.md` | `docs/explore/` 登记（pending-absorb）；立宪法访谈时自动参考 |
| 无 `.specify/memory/milestones.md` | `docs/explore/` 登记（pending-absorb）；`speckit.prd` / `speckit.milestones init` 自动吸收 |
| 当前 spec 的 prototype 未冻结未 skip | 就地修订 Demo，并在 `prototype.md` 迭代记录追加一行（日期/共识/改动） |
| spec.md 撰写/消歧阶段 | 走 `/speckit.clarify` 口径写入 `spec.md`（作为澄清记录落笔） |
| plan.md 阶段 | 写入 `plan.md` 技术决策相关小节 |
| tasks/analyze/rectify 阶段 | 按 `/speckit.rectify` 路由落笔 spec/plan/tasks，并记入分析报告当前轮次"消除过程附注" |
| implement/acceptance 阶段 | 不得直接改代码；结论经 clarify→plan→tasks 路由回流后再实现 |
| release/回顾阶段（里程碑已 done） | 写入 `milestones.md` 变更日志；涉及已发布里程碑的增强 → 转为新里程碑候选，不改历史 |

环节判定自上而下取首个命中行；"当前 spec" = `specs/` 下最新且对应里程碑未 done 的目录（与 AGENTS.md 领航提醒块的状态检测表一致）。

## 约束

- 只提问、查证、沉淀共识；本命令自身不产生新功能产物、不改代码
- 每轮必须给出推荐答案，但不许把推荐伪装成用户已确认的决定
- 沉淀结论时标注来源："经 grill 深挖确认（YYYY-MM-DD）"
- 共识若推翻已冻结产物（冻结的 Demo、已发布的里程碑），必须先请用户显式确认解冻/变更，并留痕
